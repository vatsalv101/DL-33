## 1. Historical Breaking Point: The Dictionary Look-Up Dilemma

Contrastive learning views unsupervised representation learning as a **dynamic dictionary look-up**:
Given an encoded query view $q$, the model must retrieve its matching positive key $k_+$ from a dictionary of keys containing negative distractors $\{k_-\}$.

For contrastive learning to succeed, the dictionary must satisfy two conflicting conditions:
1. **The Dictionary must be Large**: Having tens of thousands of negative samples (e.g. $K = 65,536$) samples the visual continuous feature space densely, forcing the encoder to learn fine-grained semantic distinctions.
2. **The Dictionary must be Consistent**: All keys in the dictionary should be encoded by the same or closely related encoder parameters $\theta_k$ so that queries are compared against a coherent representation space.

Prior methods could satisfy at most one condition:
- **End-to-End SimCLR**: The dictionary is the current minibatch. Gradients backpropagate through both query and key encoders. Representations are perfectly consistent, but dictionary size $K$ is bounded by GPU VRAM (scaling to $K = 4096$ requires clusters of 128+ GPUs).
- **Static Memory Bank (Wu et al., 2018)**: Stores all representations in a static memory buffer. The dictionary can hold millions of keys, but representations are severely **inconsistent**: keys in the buffer were generated by network checkpoints from epochs ago, yielding noisy gradients and training instability.

## 2. The Thought Experiment: Decoupling Dictionary Size via Queue & Momentum

Kaiming He et al. resolved this dilemma with two core architectural mechanisms:

```
                  Query View x_q           Key View x_k
                        │                        │
                        ▼                        ▼
                 Query Encoder            Key Encoder (No Grad)
                   f_q(θ_q)                 f_k(θ_k)
                        │                        │
                  Backprop Grad           Momentum Update:
                        │             θ_k ← m·θ_k + (1-m)·θ_q
                        ▼                        │
                     Query q                     ▼
                        │                   Positive Key k_+
                        │                        │
                        ├────────────────────────┤
                        ▼                        │
               [ Similarity: q · k_+ ]           ▼
                        │                  ┌───────────┐
                        │                  │   QUEUE   │ <── Enqueue k_+
                        ├─────────────────>│  k_1, k_2 │
                        ▼                  │  ... k_K  │ ──> Dequeue oldest
               [ Similarity: q · k_- ]     └───────────┘
                        │
                        ▼
             [ InfoNCE Contrastive Loss ]
```

1. **The Dictionary as a Queue (Decoupling Size from Batch Size)**:
   Instead of computing negatives within the current batch, maintain a dynamic **FIFO Queue** of negative keys of size $K$ (e.g. $K = 4,096$ or $65,536$).
   - In each training iteration, the current batch of keys is pushed into the queue (`enqueue`).
   - The oldest batch of keys is dropped (`dequeue`).
   - This decouples the dictionary size from batch size: you can use a small batch size of 64 or 256 on a single machine while still contrasting against $65,536$ negative keys!

2. **The Momentum Encoder (Ensuring Representation Consistency)**:
   Why not backpropagate gradients into the key encoder $f_k$? Because backpropagating through a queue of 65,536 keys would require unrolling computation graphs across thousands of optimization steps, blowing up GPU memory.
   
   If $f_k$ has no gradients, why not simply copy $\theta_k \leftarrow \theta_q$?
   Copying $\theta_q$ directly causes representation collapse and training divergence because keys in the queue were produced by earlier network states, creating sudden distribution shifts.

   **The Solution**: Update the key encoder via **Exponential Moving Average (EMA)**:
   $$\theta_k \leftarrow m \cdot \theta_k + (1 - m) \cdot \theta_q$$
   where $m \approx 0.999$. Because $m$ is close to 1, the key encoder evolves slowly and smoothly. Keys produced across adjacent iterations remain mutually consistent!

## 3. Mathematical Architecture & Step-by-Step Derivation

### 3.1 Contrastive InfoNCE with Queued Negatives
For a batch of $N$ queries $q \in \mathbb{R}^{N \times D}$ and their corresponding positive keys $k_+ \in \mathbb{R}^{N \times D}$, and a negative queue $Q \in \mathbb{R}^{D \times K}$:

1. **Normalize**:
   $$q = \frac{q}{\|q\|_2}, \quad k_+ = \frac{k_+}{\|k_+\|_2}, \quad Q = \frac{Q}{\|Q\|_2}$$

2. **Compute Logits**:
   - Positive logits (dot product between query and positive key):
     $$l_{\text{pos}} = \frac{1}{\tau} \sum_{d=1}^D q_{i, d} \cdot k_{+, i, d} \in \mathbb{R}^{N \times 1}$$
   - Negative logits (dot product between query and all $K$ keys in queue):
     $$l_{\text{neg}} = \frac{1}{\tau} q \cdot Q \in \mathbb{R}^{N \times K}$$
   - Concatenated logits:
     $$\text{logits} = [l_{\text{pos}} \;\|\; l_{\text{neg}}] \in \mathbb{R}^{N \times (1 + K)}$$

3. **Loss Computation**:
   Since the positive match $l_{\text{pos}}$ is always located at index 0, the ground truth labels are all zeros:
   $$\text{labels} = \mathbf{0} \in \{0\}^N$$
   $$\mathcal{L} = \frac{1}{N} \sum_{i=1}^N \left( - \log \frac{\exp(l_{\text{pos}, i})}{\exp(l_{\text{pos}, i}) + \sum_{j=1}^K \exp(l_{\text{neg}, i, j})} \right)$$

4. **Queue & Momentum Update**:
   - Update Queue: Dequeue oldest keys, enqueue current $k_+$.
   - Update Key Encoder: $\theta_k \leftarrow m \theta_k + (1 - m) \theta_q$.

## 4. Tensor Contracts & Architectural Blueprint

| Component | Input Shape | Output Shape | Notes |
| :--- | :--- | :--- | :--- |
| `MoCo.forward` | `im_q: (N, 3, H, W)`, `im_k: (N, 3, H, W)` | `(logits: (N, 1+K), labels: (N,))` | Evaluates contrastive matching against queue |
| `MoCo._momentum_update_key_encoder` | None | None | In-place EMA update $\theta_k \leftarrow m \theta_k + (1-m) \theta_q$ |
| `MoCo._dequeue_and_enqueue` | `keys: (N, D)` | None | Rolling FIFO buffer update for negative dictionary |
| `queue` | Buffer of shape `(D, K)` | Buffer of shape `(D, K)` | Maintained without gradient across steps |
